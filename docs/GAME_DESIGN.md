# GAME DESIGN — v1.0

## 1. Product concept

This project is a football prediction game with RPG-like characteristics.

The goal is not merely to ask:
> "Who will win?"

The goal is to make the user feel that they are making strategic predictions whose quality is evaluated against the actual performance and events of the match.

## 2. Core differentiator

The differentiator is a performance-aware prediction system.

The game can use real football performance data — including xG and player-level events — to evaluate prediction quality in a richer way than conventional betting-pool/bolão systems.

The game should make the player feel that:
- a prediction can be more or less sophisticated;
- match events affect the quality/value of a prediction;
- player performance matters;
- goalkeeper and attacker performance can matter;
- first-half information can matter separately from the final result;
- progression and scoring can feel like an RPG/game system.

## 3. What this game is NOT

The product must not be reduced to:
- a simple win/draw/loss pool;
- an exact-score-only game;
- a generic fantasy football game;
- a conventional betting interface;
- a simple "more correct answers = more points" system.

These could exist as components, but they must not replace the differentiated core.

## 4. Protected concepts

The following concepts are considered part of the product identity:
1. xG;
2. attacker performance;
3. goalkeeper performance;
4. first-half vs. second-half dynamics;
5. event/performance-aware scoring;
6. RPG-like progression.

## 5. Product philosophy

Complexity should exist where it creates meaningful gameplay.

Technical complexity that does not create player value should be avoided.

However, technical simplification must never remove the product's defining mechanics.

## 6. Open design items

The exact:
- scoring formula;
- weights;
- thresholds;
- XP progression;
- levels;
- badges/achievements;
- economy/rewards;
- anti-abuse rules;
- data-provider contracts;
- exact UI flows

must be maintained in the dedicated documents once finalized.

Until finalized, they are TBD and must not be invented by the AI.
